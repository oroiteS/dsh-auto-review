# 可配置自动权限审查（实验性）

基于当前 DSH 0.2.2-rc.3 自带的 `@deepseek-ai/dsh-experimental-auto-review`；原插件继续负责权限模式、审查上下文和拒绝后的批准流程。本包替换 `auto-review` 模型请求的 provider、model 和 system prompt，并兼容扩展的拒绝结果；不改变主会话的模型。

## 配置

打开侧栏 **插件 → 可配置自动权限审查 → 配置**（插件组件行上的配置按钮），在审查模型下拉框选择已配置的模型，或选择沿用会话模型；可选择该模型提供的思考强度，也可以使用模型默认值；下方文本框可以查看和编辑完整 Prompt。点击保存后，配置写入当前 DSH profile，后续审查立即使用，不重载权限门。模型需要先在 DSH 中配置并可用，本插件不会添加服务商或保存密钥。未找到路由、没有凭据、模型不支持输入或返回不合规时，本次工具调用失败并且不执行，不会静默切回主模型。

思考强度选项由 DSH 模型目录提供，不同模型可用的强度可能不同。“模型默认”使用审查模型自身的默认值，不沿用主会话的思考强度。沿用会话模型时，下拉框汇集已配置模型提供的强度；所选强度必须被实际会话模型支持，否则本次审查失败并拒绝工具调用。修改审查模型后，如果原强度不受支持，需要选择可用强度或恢复模型默认，才能保存。旧配置没有此项时按模型默认处理。

新版插件加载时读取原有 `config.json` 和其 `promptFile` 作为初始值，保留旧设置；此后以 GUI 中的值为准，不再每次审查重新读取旧文件。首次 GUI 保存后，配置写入 profile，并覆盖旧文件的初始值；直接修改旧文件**不会**改变已保存的 GUI 配置。初始 Prompt 复制自 DSH 0.2.2-rc.3 原插件的 REVIEW_POLICY；GUI 中已保存的提示词不会被插件更新覆盖。更改策略可能导致危险操作直接执行。

### 审查输出协议

保留原协议：`low` 或 `medium` 可搭配 `allow`，且不能携带 `reason`；`medium` 或 `high` 可搭配 `deny`，可选自然语言 `reason`。此外，`low` 或 `unknown` 可以搭配 `deny`，但必须带非空白字符串 `reason`。不接受 `unknown` 或 `high` 搭配 `allow`、额外字段、重复字段、非 JSON 或附加文本。拒绝的理由是普通文本，不是固定原因码，也不会被当作指令。

上游不原生支持这两个扩展组合：插件在完整接收并校验后将它们转换为上游可识别的 `medium` / `deny`；审计日志仍记录模型返回的原始风险等级。`deny` 沿用上游审批流程：`ask` 策略下可能请求用户批准，`never` 下直接拒绝，模型拒绝不会自动执行工具。此规则对 `high` 和 `unknown` 同样适用；如果不希望人工批准，请使用适当的审批策略。为安全缓冲，单次审查流超过 1 MiB 或 8192 个事件时失败并拒绝调用；扩展拒绝结果的组装文本超过 8 KiB 或块数超过 256 时，也无法适配并会拒绝调用。

## 使用

在 DSH 的插件页面添加本地目录并启用本 bundle，然后在目标会话的权限菜单中选择实验性的 **Auto review** 并确认风险。本插件会启用 DSH 自带的 Auto review 集成；不要同时安装或启用另一份原版 Auto review。已有会话或权限状态的迁移行为由原插件决定，建议新建会话验证。原版会在运行时卸载时把正在使用 Auto 的会话迁移为 Full access；移除或重载前务必先手动切换到较严格的权限模式。

审查拒绝并转交人工审批时，审批卡显示拒绝原因，以及按调用 ID 从会话记录关联的工具名、待执行命令（如有）和调用参数；原有批准和拒绝选项不变。参数按会话投影提供的 JSON 显示，PTC 子调用的参数由平台序列化，不保证是初始字节原文；双向控制及部分不可见字符会转义以防误导。命令摘要是 JSON 字符串；换行等转义字符代表原始值中的字符，较长内容可在卡片中滚动查看。提供调用 ID 时，如果找不到唯一的已开始调用或参数无法解析，卡片会提示无法确认，不应盲目批准。能成功读取审查结果且模型没有提供原因时会明确提示；其他权限门同时要求审批时，也保留其原有说明。该详情使用 DSH 的共享审批插槽，因此其他工具审批也会显示同样的调用详情；平台未提供调用 ID 时，详情及其警告均无法显示，请勿在看不到待审核内容时批准。所示内容来自关联的会话记录，不是对外部环境状态的保证。

完整参数可能包含路径、文件内容、凭据或其他敏感信息，会显示给能查看此会话审批界面的用户；请注意屏幕共享和录屏。插件审计日志仍不保存工具参数。审批卡内容按会话调用记录关联，不能据此保证外部环境或其他程序内部副作用的安全。

DSH 0.2.2 的内置警告文案不能通过公开 API 覆盖。本插件提供语言选项 **中文（可配置自动审查）**：只有在设置中选中它，权限按钮提示和确认对话框才会显示可配置审查模型及提示词的正确说明，其余文本回退到普通中文；普通中文和其他语言仍使用上游原文。此语言偏好由 DSH 共享保存；停用插件后该选项会消失，界面回退到浏览器或系统语言（无法匹配时回退英语），原有语言偏好记录不会自动清除。

这是**工具权限审查，不是代码质量审查，也不是沙箱**。原版 Auto review 允许的操作具有 Full access；LLM 可能误判。原版审查 native 工具及 PTC 内部工具调用，但不审查外层 `run_code` 或 PTC 程序内直接 Node 副作用。改用其他 provider 后，审查所需会话历史、工作目录、工具参数和自定义提示词将发送给所选 provider，请先确认隐私、数据驻留和费用。审查每次额外发起一次模型请求。更改安全策略可能导致危险操作直接执行。

## 审计日志

审查记录默认写入插件目录下的 `audit-log/`，不纳入 Git。每条 JSONL 记录包含 UTC 时间、随机审查 ID、会话和调用 ID 的 SHA-256 指纹（可用于与已知 ID 对照）、调用模式、审批策略、模型最终判决和风险等级、模型流状态、审查模型路由的 SHA-256 指纹、权限门最终决策及耗时。指纹不是匿名化保障，已知或可猜测输入仍可被比对。`unknown` 表示没有足够证据，不代表允许；`ask` 表示交给用户确认，不表示用户已批准。`outcome` 把审查失败记作 error，`gateOutcome` 是权限门原始决策；两者不是实际工具执行结果。旧日志无法补回当时未记录的信息。

协议只允许拒绝时返回理由；有理由时日志在本机进行尽力脱敏和长度限制后记录，不保存模型的自由推理、提示词或工具参数。`risk: unknown` 且 `modelStatus: success` 表示模型明确返回了 unknown；`modelStatus: unknown` 等状态下则不能据此认为模型作出了该判断。**自动脱敏无法保证去除所有路径、凭证或其他敏感内容**，请将日志视为可能含敏感信息，不要随意分享。协议禁止允许结果携带理由，因此无法记录允许理由，也不会编造理由。

每条记录不超过 2 KiB，每个文件不超过 5 MiB，日志文件总量不超过 20 MiB；启动和轮转时清除超过 7 天的记录。空间不足时删除最旧记录；该有限保留机制不是永久审计。写入队列有界，插件正常卸载时等待队列排空；进程崩溃或断电可能丢失未完成写入，写入完成不等于已执行 fsync。

如果日志初始化失败，插件不会激活；如果日志队列溢出、写入失败或检测到异常丢失，本次权限门将拒绝工具调用并在工具结果中显示 `AUTO_REVIEW_AUDIT_FAILED`，同时在宿主日志中显示固定告警。日志目录使用跨进程独占锁；异常退出可能留下 `.audit.lock`，下次启动会提示可能丢失记录并拒绝激活。确认没有其他进程使用该目录后，才可手动删除锁并重启插件。外部删除旧日志或断电造成的所有丢失无法保证都被检测到，不要依赖日志恢复被删除的数据。

## 兼容性

此扩展依赖 DSH 0.2.2-rc.3 原版插件的导出及响应协议。原版权限门与模型替换共用一个插件生命周期，不会因单独关闭重定向组件而静默恢复原版策略。DSH 升级后需重新验证。源码和初始提示词可在此目录查看；原插件仍由 DSH 提供，按其 MIT 许可使用。
